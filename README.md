# Placement Readiness Prediction System

A prototype machine-learning system that models a campus placement funnel for engineering students and predicts outcomes at each stage: **eligibility → online assessment (OA) → interviews → final selection**.

> **Important:** the dataset is **synthetic**, generated by a simulator I wrote. The project demonstrates and validates the ML workflow. It does **not** prove how real placements behave. It is a decision-support prototype for students and placement cells, not an automated hiring judge.

---

## 1. Problem Statement

During placement season, students do not know whether they meet a company's cutoffs, how ready they are for the OA, or where they stand after it. Placement cells cannot easily see where in the funnel candidates drop off. This project models the funnel stage by stage and predicts what is likely to happen next from the information available at each stage.

## 2. Scope

- **Domain:** engineering campus placements
- **Data:** synthetic (3,000 students, 12 companies, 15,000 applications), fixed seed 42
- **Tasks:** regression (OA score, final score) and classification (selected / not selected)
- **Deliverable:** reproducible pipeline, evaluated models, and a Streamlit prediction app

## 3. The Simulated Placement Funnel

All rules live in `config.py`. They are the *company process*; ML predicts outcomes from partial information.

| Stage | Inputs | Rule / process |
|---|---|---|
| 1. Eligibility (rule-based) | 10th %, 12th %, JEE percentile, CGPA | Non-dream: >70, >70, >80, >7.5. Dream: >80, >80, >90, >8.5 |
| 2. Online assessment | 5 sections: logical, quant, coding, English, behavioral | Total = 0.20 L + 0.20 Q + 0.30 C + 0.15 E + 0.15 B. Clear if total ≥ 65 **and** every section ≥ 40 |
| 3. Interviews | technical, HR | Final = 0.40 OA + 0.35 Technical + 0.25 HR (rounded to integer) |
| Selection | final score | Top 8 per company. Ties broken by higher coding score |

12 companies (8 non-dream, 4 dream); each student applies to 5.

### Funnel counts (from the generator)

| Stage | Count |
|---|---|
| Applications | 15,000 |
| Eligible applications | 2,990 (2,819 non-dream, 171 dream) |
| Cleared OA | 960 (840 non-dream, 120 dream) |
| Selected | 96 (8 × 12 companies) |

## 4. Hypotheses and Results

| # | Hypothesis | Test | Verdict |
|---|---|---|---|
| H1 | OA scores add more predictive value for selection than interview scores | AUC gain B−A vs C−A (grouped CV) | **Rejected.** +0.107 vs +0.176 (logistic regression); interviews carry 60% of the final score |
| H2 | Coding score predicts technical interview performance beyond OA total | Regression coefficient with student-level bootstrap CI; permutation importance | **Supported.** Coefficient 0.152, 95% CI [0.069, 0.237], excludes 0 (planted 0.25, slightly underestimated) |
| H3 | The coding tie-break decides a measurable share of final seats | Count ties at the cut line | **Supported as a frequency.** Decided the last seat at 6 of 12 companies. Says nothing about fairness |

H2 and the planted-weights check validate the *method*, because the effects were built into the simulator.

## 5. Key Results

**Selection classification** (960 interviewed applications, 96 selected, 5-fold stratified grouped CV):

| Features | Logistic regression AUC | Random forest AUC |
|---|---|---|
| A: academics | 0.793 | 0.754 |
| B: A + OA sections | 0.900 | 0.886 |
| C: A + technical, HR | 0.969 | 0.966 |
| D: all | 0.987 | 0.981 |

**Regression** (5-fold grouped CV):

| Task | Model | MAE | RMSE | R² |
|---|---|---|---|---|
| OA total from academics | Dummy (mean) | 7.34 | 9.11 | −0.001 |
| | Linear | **4.36** | **5.45** | **0.641** |
| | Random forest | 4.54 | 5.66 | 0.613 |
| Final score from academics + OA | Dummy (mean) | 5.16 | 6.38 | −0.007 |
| | Linear | **3.81** | **4.71** | **0.448** |
| | Random forest | 4.02 | 4.99 | 0.383 |

**Backtest at the OA cutoff** (out-of-sample, grouped by student): precision **0.79**, recall **0.71**.

Linear models slightly beat random forests because the simulator is built from linear formulas. This is a property of the synthetic data, not a general claim.

## 7. Methodology

Data → Cleaning → EDA → Feature Selection → Training → Testing → Evaluation → Prediction

1. **Data generation.** Correlated academics (10th → 12th → JEE → CGPA) built with a z-score mixing formula. A hidden per-student skill drives OA sections (CGPA 50%, 10th 15%, 12th 15%, JEE 5%, individual randomness 15%). Interviews depend on OA with extra noise. Deliberate mess is injected.
2. **Cleaning** (`src/cleaning.py`). Removes duplicates, converts `"82%"` text to numbers, blanks impossible percentages, fixes CGPA typos (85 → 8.5), recovers student-level values from the student's other applications, and solves a single missing OA section from the known total. Validated against `placement_truth.csv`.
3. **EDA** (`03_eda.ipynb`). Six charts, each filtered to rows that reached that stage.
4. **Feature selection** (`04_feature_selection.ipynb`, `src/features.py`). Leakage columns excluded; correlation and mutual information used as evidence.
5. **Modelling** (`05_modelling.ipynb`). Models A-D, logistic regression and random forest, grouped stratified CV by `student_id`, imputers inside pipelines.
6. **Evaluation** (`06_evaluation.ipynb`). H1-H3, regression tasks, planted-weights check, out-of-sample backtest, final models saved with `joblib`.
7. **Prediction system** (`src/predict.py`, Streamlit app).

### Injected mess (and what cleaning found)

| Mess | Injected | Handled |
|---|---|---|
| Duplicate rows | 146 | 146 removed (15,146 → 15,000 rows) |
| Percentages as text | 858 cells | converted |
| Impossible percentages | 86 | 85 blanked, then recovered from the student's other rows |
| CGPA typos (×10) | 79 | 77 corrected |
| JEE missing (per student) | 253 students, 1,265 rows | kept missing, `jee_missing` flag, imputed inside the model pipeline |

Rows that never reached a stage keep NaN in that stage's columns on purpose ("never happened" is not "missing").

## 8. Prediction App

```bash
streamlit run app/streamlit_app.py
```

| Tab | What it does |
|---|---|
| 1. Before the OA | Rule-based eligibility, gap table if ineligible, expected OA total, rough chance of clearing, readiness verdict |
| 2. After the OA | Enter 5 section scores → OA cleared?, selection score, expected final score |
| 3. What-if simulator | Vary one academic value and see the expected OA total change |
| 4. Model Performance | Out-of-sample scatter, precision/recall at cutoff, result tables, AUC chart |

Notes on interpretation:
- The verdict says **readiness**, never "fit" or "you will be placed".
- `selection_score` is a **ranking score**, not a probability (`class_weight="balanced"` inflates it). The app shows it relative to the 10% base rate.
- The verdict thresholds (40% / 70% clearing chance, 2× base rate) are my own choices, not calibrated values.

## 10. Limitations and Ethics

- **Synthetic data.** Accuracy shows the method works on a process I simulated, not on real placements.
- **Linear simulator favours linear models.** The wins of logistic and linear regression are partly an artefact.
- **Selection depends on competitors.** "Top 8 per company" means one student's label depends on others, so cross-validation across companies is an approximation.
- **Selection bias.** Real cutoffs hide how below-cutoff students would have performed.
- **Small positive class.** Only 96 selected students (about 19 per CV fold), so metrics are noisy.
- **Repeated students.** A student appears in up to 5 rows. Grouped splits handle this, but backtest precision and recall are over applications (about 1,000 effective students).
- **Fairness.** 10th %, 12th % and JEE can reflect background advantages. The tool shows readiness gaps; it must not rank or reject candidates.
- **No causal claims.** Correlation is not causation.
